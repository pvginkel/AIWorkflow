# The close-out template — the store and the report, mechanically

The concrete shapes of a slice's close-out report: the store `close-out.json`, which is the
record, and `close-out.md`, which `${CLAUDE_PLUGIN_ROOT}/tools/close_out.py render` writes from
it. No author types either — the tool writes every entry, note, strike and ruling, and its
verbs are listed [below](#the-verbs). Semantics — what the report is for, the labels and the
routes, who writes what and when, the entry rules, the lifecycle — are
[close-out.md](close-out.md); this doc is the shape.

## The store

```json
{
  "store": 1,
  "slice": "NNN_<slug>",
  "closed": null,
  "entries": [
    {
      "id": "B3",
      "kind": "defect",
      "grade": "minor",
      "headline": "controller: the roll's status line reports …",
      "body": ["<the body, one string per line>"],
      "consequence": "<what is experienced, and what has to happen for it to be reached>",
      "evidence": "witnessed",
      "author": "code-reviewer, P3 r1",
      "labels": {"trigger": "ordinary-condition", "impact": "broken", "signal": "silent",
                 "fix": "design", "area": "sensitive", "repo": "KubeCoder"},
      "notes": [{"by": "consult 1", "date": "2026-09-30", "text": ["<one string per line>"]}],
      "wrap_up": null,
      "strike": null,
      "ruling": null
    }
  ]
}
```

- **Entries stand in order of arrival**, and an id is never reused: the next number under a
  kind's letter counts every entry that carries the letter, struck ones included.
- **Text is kept as lines** — `body`, and the `text` of a note — so that a diff of the store
  reads like a diff of text.
- **`labels`** holds the labels of the entry's kind, by the names and values of
  [close-out.md](close-out.md#the-labels); `null` on an entry that has none yet. A correction
  (`relabel`) changes them in place and leaves a note that says what changed and why.
- **`wrap_up`** is what the wrap-up did with an entry it did not strike: `{"outcome", "by",
  "date", "text"}`, the outcome being `card` (it asks for a card) or `left` (it looked and
  changed nothing).
- **`strike`** is `{"reason", "by", "date", "commit"}`, the commit where a fix resolved the
  entry; **`ruling`** is `{"words", "did", "date"}` — the operator's words, never edited, and
  what the session did on them.
- **`closed`**, on the report, is `{"date", "words"}` once the operator has closed it.
- **The route is not in the store**, and neither is the run header: the first is computed from
  the labels at every render, the second is `state.json`'s.
- An entry imported from a report in Markdown also carries `section`, the heading it stood
  under, and keeps the id it had.

## The report

```markdown
# Close-out — slice NNN <slug>

<!-- Generated by `close_out.py render` from close-out.json, the record. The `Disposition:`
     lines are yours to write; everything else is overwritten by the next render. -->

Run: <not yet stamped>

## Comes to you

## Card requests

## For the wrap-up

## Unlabelled

## Closed

## Record
```

| section | holds | shown |
|---|---|---|
| Comes to you | actions, decisions, risks, and the improvements that are the operator's to weigh | in full |
| Card requests | what the table or the wrap-up asks a card for | in full, with what the wrap-up found |
| For the wrap-up | what waits for the wrap-up; empty once it has run | body folded |
| Unlabelled | entries without labels, until they have them | in full |
| Closed | what the table closed, and what the wrap-up looked at and left | body folded |
| Record | the run's events that describe no problem; then what was struck — by the run, by the wrap-up, on the operator's word | folded whole |

`render` writes the sections that hold something, in this order. Inside a section the order is
the grade (`major`, `minor`, ungraded, `nit`, `cosmetic`), then the kind in the order of
[its table](close-out.md#the-labels), then the id; in the Record the events come first and the
struck entries after them, each by id.

## The entry

In full:

```markdown
### B3 — controller: the roll's status line reports … · minor

<the body, as many paragraphs as it takes; then every note, a dated paragraph each:
`<who>, <date> — <text>`>

**Consequence:** <what is experienced, and what has to happen for it to be reached>

**Triage:** defect · shows on an ordinary condition · breaks a flow · silent · fix needs
design · sensitive area · in KubeCoder
**Provenance:** witnessed — code-reviewer, P3 r1
**Route:** the wrap-up — fix within its bar, or ask for a card
**Disposition:**
```

The heading is `### <id> — <headline>`, with ` · <grade>` appended where the entry has one.
`**Triage:**` is the entry's labels in words and `**Route:**` where the table sent it and on
which ground; both are `render`'s, from the store. `**Provenance:**` opens with the evidence
class. `**Disposition:**` carries the operator's words, then ` — ` and what was done on them;
blank until they rule. What the wrap-up did with an entry, and every correction of a label,
stands among the notes.

An improvement shows its own labels the same way:

```markdown
**Triage:** improvement · a user is better off · felt in use · adjusts what exists · needs
design · a product call · in KubeCoder
**Route:** to you — an improvement
```

With its body folded, the lines the operator triages on stay in view:

```markdown
### B7 — <headline> · nit

<details><summary>body</summary>

<the body and its notes>

</details>

**Consequence:** …

**Triage:** …
**Provenance:** …
**Route:** closed — it needs a fault
**Disposition:**
```

And struck, or an event in the Record, it is folded whole — an event under its plain heading,
its fold reading `kept for the record`:

```markdown
### ~~B5 — <headline> · minor~~ — resolved by P4 (19640d9): suite re-run; struck by consult 1

<details><summary>struck — kept for the record</summary>

<the entry as it was in full>

</details>
```

## The run header

One block of plain lines replacing `Run: <not yet stamped>`, written by `render` from
`state.json` when the slice folder holds one — every piece present in the state, nothing
guessed for the pieces that are not:

```markdown
Run: 2026-08-14 19:49 → 23:53 · 11 phases (8 planned, P9–P11 appended) · 2 bail-outs ·
1 test round · doc phase done · $118.41 (planner 18 %, research 4 %, rework 14 %)
```

## The verbs

Every verb takes the slice directory or the report's path as its first argument.

| verb | whose | what it does |
|---|---|---|
| `init` | the loops | creates the store and renders it; an existing store is never touched |
| `labels` | an author | prints [the labels](close-out.md#the-labels) |
| `append` | an author | adds one entry with its labels; prints its id |
| `list` | an author | ids, headlines and Consequence lines by kind, struck entries marked |
| `note` | anyone | adds a dated paragraph to one entry |
| `strike` | whoever resolved the entry | strikes it, with the reason and the commit |
| `relabel` | the wrap-up | gives an entry its labels or corrects them, with a note of what it found |
| `request-card` | the wrap-up | asks for a card on an entry, with how it is reached and what the fix takes |
| `leave` | the wrap-up | records that it looked at an entry and changed nothing, and why |
| `worklist` | the wrap-up, the close-out session | what waits for the wrap-up, entry by entry, with what is asked of each |
| `rule` | the close-out session | records the operator's words on an entry and what was done on them; without an id, reads the `Disposition:` lines of `close-out.md` back into the store |
| `close` | the close-out session | closes the report on the operator's word: every entry still live is closed by it, but one that carries a ruling nobody executed — that one stays, and the report stays open over it |
| `render` | the loops, the skills | reads the `Disposition:` lines back, then writes `close-out.md` from the store |
| `stamp` | `/dev:run-slice` | `render`, printing the run header |
| `counts` | the loops, `/dev:run-slice` | live entries per section of the report and per id letter, on one line |
| `import` | the close-out session | reads a report in Markdown into a store, once |

`render` never loses what the operator wrote: a `Disposition:` line that differs from what the
store would render is taken into the store, by the entry's id, before the file is written.
