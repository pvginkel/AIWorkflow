## 1. T4 — the mechanism

- **Whole-plan reads before the first edit: 0 of 16 writer sessions.** Corpus: 182 of 184 writer
  sessions read plan.md at least once, ≈ 1 before editing. Every remaining plan.md touch in the
  new sessions is the done-record append — `grep -n "^###"` for the heading, `sed -n` on the
  region, a python heredoc insert, commit (2–3 "reads" per session, all after the first edit). The
  one pre-edit read (175 P3, `grep -A 60 "### P4" plan.md`) was the writer wanting the *next*
  phase's body, which the digest gives as heading + Target only — a legitimate read by design.
- **No `verification.json`, `slice.md` or project `CLAUDE.md` reads** before editing (corpus:
  ≈ 1 verification.json read per session). Turn 1 is `git branch --show-current` (+ `git status`)
  and the target source file; fix rounds open on `code_review_r1.md`. What remains of orientation
  is code comprehension — the target file, its tests, the harness/fixtures — chained 2–4 reads per
  Bash call; three sessions ran `kc project info` for the gate command the digest already carries.

## 5. Confounds to carry into the next read

1. **Claude Code 2.1.241.** The writers made **zero `Read` / `Edit` / `Write` tool calls in 16 of 16
   sessions** — every read is `sed -n` / `cat` / `grep`, every edit a heredoc, `python3 -` script or
   `sed -i`. The shift began at 2.1.234 in the corpus (0 of 111 sessions without an Edit call
   through 2.1.233; 43 of 73 from 2.1.234 on) and is therefore in the corpus tail, but the 2–4
   band mixes editing styles. `orient_w` (turns before the first Edit/Write *tool* call — what
   `slice_cost.py`'s `orient` column reports) is meaningless for these sessions; `first_edit_turn`
   is the measure.
2. **Effort period.** The band's early slices ran under other effort settings: writers there think
   2.7 k tokens per session at the median, the 16x–170 tail 11.3 k, the new sessions 10–12 k. Output
   per turn and thinking compare only against the tail.
3. **Size.** Phase count is the band match, but 174/175/179's phases are small; 173 carries the real
   controller work and is the expensive one. `git show --shortstat` per phase commit would be the
   size control if the next slices make it necessary.
