## Core results

LLM4FPM (eCPG-Slicer = precise line-level slicing; FARF = complete cross-file context) vs. baseline LLM4SA (whole-function-body context), open-source qwen2.5-32b throughout.

- Juliet (7194 warnings, 7 CWEs, Cppcheck/Infer/CSA): F1 >99% across CWEs (Abstract); CSA F1 93.48%→99.75%; Infer F1 88.65%→99.57% (RQ1).
- D2A (libtiff, 881 instances): label accuracy raised from ~53% (noisy original) to 86% per 50-case check (RQ1; Conclusion later says "82%" — inconsistency).
- Real-world (8 GitHub projects, 2.56M LOC): of 43 confirmed FPs among 50 sampled, LLM4FPM flagged 37 (86.05%); Abstract states >85% overall (RQ2).
- Ablation: full 98.17% Acc/98.92% F1; no-FARF → 90.16%/94.39%; no-slicer → 95.15%/97.19%, plus 40 cases failed via context overflow (RQ3).
- Case study: function-only context misled the LLM into confirming a bug; traced multi-file context gave correct FP dismissal (RQ3).
- Cost: 4.7s/warning; $0.384/warning, $2758.87 total savings vs. GPT-4 pricing on Juliet (RQ4).

## Relevance to A/B/C

- **A** (deep-dive regardless of size): no direct evidence — complexity-tiered routing untested. Weak signal: one fixed lightweight model/pipeline runs on every warning to isolate context quality from effort; RQ2 notes slices can still span hundreds/thousands of lines — complexity varies but is never routed on.
- **B** (comment churn / claim-strength wording): none directly — comments are never discussed, only SAST bug TP/FP classification. Only an analogy: context-grounded re-judgment applies to any LLM-raised finding, including comment-staleness flags.
- **C** (unbounded work amplification): relevant. Individually-plausible warnings, left untriaged, erode trust and drive abandonment (Johnson/Christakis&Bird) — the same shape as unbounded raised-then-fixed work. LLM4FPM's second pass strips out most (>85% real-project) non-actionable findings before they reach fix work.

## Supported interventions

1. Insert a context-grounded FP-triage pass between reviewer finding and coder fix, feeding it a precise slice plus complete cross-referenced context, not just the diff hunk — backed by the ablation, where precision and completeness each independently raised accuracy.
2. Never give a fixer only the local snippet for a claim; trace referenced definitions across files — backed by the case study where function-only context turned a correct FP into a wrongly-confirmed bug.
3. Keep the pass cheap and default-on, not size-gated — backed by RQ4's low per-item cost, arguing for context quality over complexity routing (bears on A).
4. Use self-consistency (majority vote) as the triage rule — part of LLM4FPM's design, a low-cost robustness knob (not separately ablated).

## Applicability caveats

Domain is narrow: C/C++ SAST warnings via program-analysis graphs (Joern CPG/AST/CFG/PDG); no equivalent slicer exists for our artifacts. Model is self-hosted qwen2.5-32b, not Opus 5; transfer to larger-context proprietary models untested. Verification samples are small (50+50), rated only by the paper's own authors. RQ2 shows precision benefit degrades on complex real code. Paper is Nov 2024 (updated May 2025); the cited 2013/2016 literature predates LLM tooling and concerns classic non-LLM SAST tools.
