## Core results

TALE (Han et al. 2024, arXiv 2412.18547) injects a per-question "token budget" into the CoT prompt ("...and use less than β tokens") and shows CoT reasoning is far more verbose than needed:

- **TALE-EP** (self-estimated budget, no fine-tuning), averaged over GSM8K/GSM8K-Zero/MathBench (4 tiers), on GPT-4o-mini: 81.03% accuracy vs. Vanilla CoT's 83.75% (−2.7pp), output tokens 148.72 vs. 461.25 (**68.64% reduction**), expense 118.46 vs. 289.78 (**~59% reduction**) — Table `tab:main_eval`.
- Cross-model generalization on MathBench-College (GPT-4o, GPT-4o-mini, Yi-lightning, o3-mini): **64.63%** avg token reduction, **45.30%** avg expense reduction vs. Vanilla CoT, comparable accuracy — except GPT-4o-mini drops 8pp (78%→70%), attributed to its smaller size struggling within a tight response (Table `tab:generalization`, §5.2).
- **Token Elasticity**: budgets set too aggressively backfire — a 10-token budget produced *more* actual tokens (157) than a 50-token budget (86) on the same GPT-4o-mini example; models that can't hit a too-small budget ramble more, not less (§3, Fig. `motivation_elastic_observation`).
- **TALE-PT** (SFT/DPO post-training on Llama-3.1-8B-Instruct): cuts tokens ~50% vs. Vanilla CoT with competitive/better accuracy (§5.3, Table `tab:internalization`).
- **Overthinking hurts on easy tasks**: on GSM8K-Zero (answer embedded in question) with **Llama-3.1-8B-Instruct**, Vanilla CoT accuracy (65.04%) is *lower* than Direct Answering (70.32%) — "attributed to overthinking" (§5.3). Note: this reversal did **not** hold for the larger models on GSM8K-Zero in `tab:main_eval` (Vanilla CoT 99.50% > Direct 97.21%) — it's model-size-dependent, not universal.
- Budget self-estimation is imperfect: only 60.61% in-range accuracy vs. the optimal searched range, 109.64-token average offset when wrong (Appendix).

## Relevance to A/B/C

- **A (yes, directly)**: TALE-EP is exactly "route compute by task-complexity" — but implemented as a *continuous, same-model, per-question prompt budget*, not discrete model/effort routing. The GSM8K-Zero/Llama result is direct evidence that unthrottled deep reasoning actively hurts accuracy on easy tasks (not just costs money).
- **B (none)**: paper only concerns ephemeral CoT reasoning tokens discarded after the answer, never persistent code artifacts, comments, or multi-turn staleness. No transfer.
- **C (none)**: no multi-agent review/fix loops or aggregate-finding dynamics are studied; the binary-search budget-finding procedure is a training-time search, not a reviewer-amplification analog.

## Supported interventions

1. Give the coder/planner an explicit **per-task token/length budget in the prompt**, scaled to estimated complexity, rather than routing to a different model/effort tier — supported by the 67-69% token cut with <3pp accuracy loss (Table `tab:main_eval`).
2. **Don't set budgets too tight** — calibrate toward a "reasonable" range, not the minimum; overly small budgets increase output (Token Elasticity, §3).
3. Use **self-estimation**: have the model itself judge required effort zero-shot before acting, rather than an external heuristic classifier — the failed prior approach — since LLM-estimated budgets tracked optimal budgets reasonably well (§4.2, Appendix budget-estimation results).
4. On genuinely simple/trivial tasks, actively cap planner depth rather than merely tolerate verbosity — accuracy, not just cost, can benefit (GSM8K-Zero/Llama finding).

## Applicability caveats

Task domain is single-turn math-word-problem QA graded by exact match; the one non-math generalization test (code summarization, empathetic response, code generation, Appendix) shows *larger* quality (BLEU) degradation under budgeting — weak evidence for coding-adjacent tasks. Models tested: GPT-4o(-mini), Yi-lightning, o3-mini, Llama-3.1-8B — no Claude/Opus, no models with native extended-thinking budgets. No multi-step agentic or multi-agent-review setting tested. TALE-PT needs fine-tuning, incompatible with a no-per-task-tuning generic loop; only TALE-EP transfers. Work is Dec 2024–Jun 2025, predating current built-in reasoning-budget controls.

## Briefing check

**Nuance, not flat confirm.** "Disproportionate compute on easy problems hurts" is evidenced only once, for the smallest model (Llama-3.1-8B) on GSM8K-Zero — the same reversal does *not* appear for GPT-4o/4o-mini/Yi/o3-mini in the main table, where Vanilla CoT still beats Direct Answering there. The paper's dominant finding is closer to "CoT is uniformly over-verbose relative to a well-chosen budget regardless of difficulty" (68% token savings hold across all MathBench tiers) rather than "only easy tasks get hurt by extra thinking." Task-dependence shows up as *degree* (harder tiers tolerate/need larger budgets) more than as a binary helps/hurts split.
