# UX Design Document Template

Use this template for feature work, redesigns, and implementation handoffs. Omit sections that do not add value.

## 1. Summary

- Feature or problem
- Why it matters
- Recommended direction in 2-4 sentences

## 2. Users and Goal

- Primary user or audience
- Trigger or entry point
- User goal
- Product goal or business intent if known

## 3. Problem Framing

- Current friction or failure mode
- Constraints already known
- Assumptions that affect the proposal

## 4. Proposed Experience

Describe the intended experience from entry to completion. Explain:

- Information hierarchy
- Main actions
- Decision points
- Feedback shown to the user
- What makes this flow easier or safer than the current state

## 5. Interaction Details

Break down the UI into implementation-facing behaviors.

- Page or screen structure
- Sections or components in order
- Primary, secondary, and destructive actions
- Visibility rules
- Default values, selections, and progressive disclosure

## 6. States and Edge Cases

Cover the states the frontend must support.

- Initial state
- Loading or skeleton state
- Empty state
- Success state
- Validation state
- Error state
- Permission or access state
- Destructive confirmation or undo behavior if relevant

## 7. Responsive Behavior

Explain what changes across breakpoints.

- Layout shifts
- Content priority
- Navigation changes
- Touch-specific behavior

## 8. Accessibility

Specify the minimum accessibility expectations.

- Keyboard flow and focus handling
- Semantic structure and labels
- Error announcements and helper text
- Hit target, contrast, and motion considerations

## 9. Content and Microcopy

Call out text that matters to comprehension or trust.

- Labels
- Button text
- Helper text
- Empty-state copy
- Error messages
- Confirmation text

## 10. Developer Handoff

List the behaviors a frontend developer should implement.

- Component list
- Interaction rules
- Data dependencies or assumptions
- Analytics or telemetry suggestions if explicitly relevant
- Acceptance criteria in plain language

## 11. Open Questions

List unresolved items that need product, design, or engineering input.
